# Electronic Health Record (EHR) & Database Architecture

This document describes the database architecture for the Evionex and GeneSetu platforms, focusing on data structures, role-based access control (RBAC), and the overall system design.

> **NOTE:** This file must be kept updated whenever changes are made to the database schema, RLS policies, or authentication flow to ensure AI models have accurate context for development.

## 1. Evionex Database Architecture (Project ID: `wepnxeuklvvddgrlezyd`)

The Evionex database is a multi-tenant healthcare ecosystem connecting Patients, Doctors, Institutions, and Administrative staff.

### 1.1 Core Data Entities & Schema Details

#### Identity & User Management
- **`evionex_profiles`**: The central identity table linked to `auth.users`.
    - `id` (uuid): Primary key, matches `auth.users.id`.
    - `role` (USER-DEFINED): Primary role (Admin, Employee, Doctor, Institution, Patient).
    - `sub_role` (USER-DEFINED): Granular role for specific permissions.
    - `account_status` (USER-DEFINED): Status of the account (e.g., Active, Pending, Suspended).
    - `full_name`, `phone`, `email` (text): Basic user contact information.
    - `created_at`, `updated_at` (timestamp): Audit timestamps.

#### Healthcare Provider Ecosystem
- **`evionex_doctors`**: Specialized profiles for healthcare providers.
    - `id` (uuid): Primary key.
    - `doctor_id` (text): Internal identifier.
    - `specialization`, `qualification` (text): Professional details.
    - `license_number` (text): Medical license for verification.
    - `institution_id` (uuid): FK to `evionex_institutions`.
    - `experience_years` (integer), `consultation_fee` (numeric).
- **`evionex_institutions`**: Healthcare facilities.
    - `id` (uuid): Primary key.
    - `institution_code` (varchar): Unique identifier for the facility.
    - `name`, `address`, `email`, `phone`, `website` (text).
    - `username` (text): Login identifier for the institution.
- **`evionex_employees`**: Internal Evionex staff.
    - `id` (uuid): Primary key.
    - `employee_id` (text): Internal staff ID.
    - `department`, `designation` (text).
    - `pan_encrypted`, `aadhaar_encrypted` (text): Encrypted sensitive data.
    - `resume_file_path` (text): Path to stored resume in Supabase Storage.
    - `education_history`, `work_history` (jsonb): Structured professional background.
    - `salary` (numeric), `date_of_joining` (date).
    - `first_login_complete` (boolean): Onboarding flag.
- **`evionex_patients`**: Patient-specific clinical data.
    - `id` (uuid): Primary key.
    - `patient_id` (text): Internal patient ID.
    - `date_of_birth` (date), `gender`, `blood_group` (text).
    - `address` (text), `emergency_contact_name`, `emergency_contact_phone` (text).
    - `assigned_doctor_id` (uuid): FK to `evionex_doctors`.

#### Relationships & Workflow
- **`evionex_doctor_patients`**: Junction table for Doctor-Patient assignments.
    - `doctor_id`, `patient_id` (uuid): Composite keys.
    - `assigned_at` (timestamp).
- **`evionex_connection_requests`**: Patient requests to connect with doctors.
    - `patient_id`, `doctor_id` (uuid).
    - `status` (text): Pending, Accepted, Rejected.
- **`evionex_doctor_institution_requests`**: Doctors requesting to join institutions.
    - `doctor_id`, `institution_id` (uuid).
    - `status` (text): Pending, Accepted, Rejected.

#### Clinical Data & Communication
- **`evionex_medical_reports`**: Storage metadata for medical files.
    - `patient_id` (uuid), `report_type` (text).
    - `file_path` (text): Path in Supabase Storage.
    - `uploaded_by` (uuid): User who uploaded the report.
    - `visible_to_patient` (boolean): Privacy toggle.
- **`evionex_notifications`**: System alerts.
    - `user_id` (uuid), `type`, `title`, `message` (text).
    - `is_read` (boolean), `metadata` (jsonb).

### 1.2 User System & Authentication
- **Auth Implementation**: Uses **Supabase Auth** (GoTrue).
- **Identity Flow**: `auth.users` (managed by Supabase) $\rightarrow$ `evionex_profiles` (public table).
- **RBAC**: Access is governed by Row Level Security (RLS) policies.
- **Authorization Logic**: Centralized via SQL helper functions:
    - `evionex_is_active_user()`: Checks if the user is authenticated and active.
    - `evionex_get_sub_role()`: Retrieves the specific sub-role for permission checks.

### 1.3 Payment System & Razorpay Integration
The system uses a secure flow where critical financial writes are handled by **Edge Functions** using the Service Role.

#### Tables
- **`orders`**: Tracks payment intents.
    - `id` (uuid): Primary key.
    - `razorpay_order_id` (text): The ID generated by Razorpay API.
    - `amount` (integer): Amount in smallest currency unit (e.g., paise).
    - `currency` (text): e.g., "INR".
    - `plan_name` (text): The subscription plan purchased.
    - `status` (text): created, attempted, paid, failed.
    - `customer_name`, `customer_email` (text).
    - `receipt` (text): Razorpay receipt ID.
- **`payments`**: Tracks actual payment transactions.
    - `id` (uuid): Primary key.
    - `order_id` (uuid): FK to `orders`.
    - `razorpay_payment_id` (text): Unique payment ID from Razorpay.
    - `razorpay_order_id` (text): Redundant check for the order.
    - `razorpay_signature` (text): Used to verify the payment authenticity.
    - `verified` (boolean): Flag indicating the signature was successfully validated.

#### Financial Flow
1. **Order Creation**: Client $\rightarrow$ Edge Function $\rightarrow$ Razorpay API $\rightarrow$ Create `orders` record $\rightarrow$ Return `razorpay_order_id` to client.
2. **Payment**: Client $\rightarrow$ Razorpay Checkout $\rightarrow$ Payment Success.
3. **Verification**: Client $\rightarrow$ Edge Function (with payment details) $\rightarrow$ Verify Signature $\rightarrow$ Create `payments` record $\rightarrow$ Update `orders.status` to 'paid'.

## 2. GeneSetu Database Architecture (Project ID: `bpcprnncbdjjxzqpumzy`)

GeneSetu focuses on genomic data and personalized health insights. It uses a more consumer-centric health tracking model.

### 2.1 Core Data Entities

#### User Profiles & Health Metrics
- **`profiles`**: Extended user profiles for health tracking.
    - `id` (uuid): Primary key, matches `auth.users.id`.
    - `full_name`, `username`, `avatar_url` (text).
    - `height`, `weight` (numeric), `age` (integer).
    - `country`, `city`, `gender` (text).
    - `exercise_frequency`, `work_activity`, `marital_status` (text).
    - `onboarding_completed`, `questionnaire_completed`, `terms_accepted` (boolean).
    - `is_premium` (boolean), `subscription_tier` (text), `subscription_expiry` (timestamp).
    - `storage_usage`, `storage_limit` (bigint).
    - `current_streak`, `consecutive_days`, `streak_goal_days`, `streak_freezes` (integer).
    - `last_activity_date` (text).

#### Health Tracking & Logs
- **`medications`**: User's prescribed medications.
    - `name` (text), `type`, `dosage`, `frequency` (text).
    - `times` (jsonb): Schedule of doses.
    - `start_date` (date), `notes` (text).
    - `active`, `archived` (boolean).
- **`medication_logs`**: Tracking of medication intake.
    - `medication_id` (uuid), `timestamp` (timestamp), `status` (text).
- **`nutrition_daily`**: Daily nutrient intake.
    - `date` (date), `calories`, `protein`, `fat`, `carbs`, `fiber` (integer).
    - `water` (double precision).
- **`nutrition_weekly`**: Aggregated weekly nutrition.
    - `start_date` (date), `avg_calories`, `avg_protein`, etc. (double precision).
- **`medical_documents`**: User-uploaded health records.
    - `name`, `reason` (text), `file_path` (text), `file_type` (text).

#### Gamification & Social
- **`game_daily_results`**: Daily scores for health games.
    - `game_type` (text), `score_value` (double precision), `played_at` (date).
- **`game_monthly_stats`**: Monthly performance analytics.
    - `game_type` (text), `month_year` (text), `mean_score`, `std_dev` (double precision).
- **`families`**: Grouping users for shared health goals.
    - `name` (text), `family_code` (text), `creator_id` (uuid).
- **`family_members`**: Junction table for family membership.
    - `family_id`, `user_id` (uuid).

#### Other Entities
- **`promo_codes`**: Discount codes for premium tiers.
    - `code` (text), `discount_type`, `discount_value` (double precision).
    - `expiry_date` (timestamp), `max_uses`, `current_uses` (integer), `active` (boolean).
- **`sharing_links`**: Controlled access to health data.
    - `owner_id`, `viewer_id` (uuid), `role` (text), `permissions` (jsonb).
- **`appointments`**: Booking for genomic tests.
    - `test_type` (text), `appointment_date` (timestamp), `status` (text).

### 2.2 User System & Auth
- **Auth Implementation**: Uses **Supabase Auth**.
- **Identity Flow**: `auth.users` $\rightarrow$ `profiles`.
- **Premium Access**: Managed via `is_premium` and `subscription_tier` columns in the `profiles` table.

## 3. Summary of Data Flow Across Projects

1. **Identity**: User $\rightarrow$ `auth.users` $\rightarrow$ `profiles` (Project specific).
2. **Clinical Flow (Evionex)**: Patient $\rightarrow$ Request Connection $\rightarrow$ Doctor $\rightarrow$ Institution.
3. **Financial Flow (Evionex)**: User $\rightarrow$ Edge Function $\rightarrow$ Razorpay $\rightarrow$ `orders` $\rightarrow$ `payments`.
4. **Health Tracking (GeneSetu)**: User $\rightarrow$ Log Nutrition/Medication $\rightarrow$ Update `profiles` (Streaks/Stats).
5. **Administrative Flow (Evionex)**: Admin $\rightarrow$ Manage $\rightarrow$ Employee/Institution/Doctor.
